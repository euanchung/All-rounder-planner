# v9 개발 과정

사용자 요청: 제목에서 날짜·과목·분류·난이도·중요도 토큰을 분리하되 소요 시간은 수동 입력, 마감/소요 시간/중요도/난이도 순서를 지키며 빨리 수행, 컨디션, 두 색 테마, 학교 일과 공유, 사용자 간 소통 개선.

후속 요청: 테스트 회원을 없애고 관리자만 유지, 월수 9교시 자생·화 9교시 동아리, 달력 아래 선택 할일, 이름/ID 검색 1:1 대화, 오늘/내일 급식 팝업, 수업 시작 시각 마감·지난 항목 숨기기. 이메일·비밀번호 방식 유지 및 선생님 계정 삭제 승인받음.

수정 과정:
1. 2분 스피치가 소요 시간으로 변하는 문제를 해결하기 위해 workload 숫자 추출을 제거. 수동 필드 미입력 시 배치·저장 금지.
2. 단어 제거 후 3쪽이라는 제목이 여러 과목에 생기는 사례를 발견. 중복 기준과 목록 표시를 과목·세부 분류까지 확장.
3. 역순 배치를 순방향으로 전환. 부드러운 분할 한도와 마감 보호 재배치, 수동 배치 보존을 테스트. 무작위 60세트의 작업량 보존·용량 제한 검증.
4. 공유 시간표 동시 수정 및 날짜 타입의 시간대 오차를 확인해 CAS·date 텍스트 반환 적용.
5. 화면별 제한된 채팅 새로고침, 서버 읽음 상태 부재를 수정. 실제 다중 계정 검사 44항목에서 원격 수신·중복 방지·권한 차단 확인.
6. 테스트 계정 정리가 이메일 대소문자 차이로 건너뛰어진 문제 확인. 정확한 삭제 대상을 검사해 정리하고 계정 수 재조회. 이후 테스트에서는 운영 DB 가입 금지, 로컬 mock으로 UI 확인.
7. 후속 화면·마감 수정은 로컬 UI 14항목 검사. 회원·API 인증 데이터는 실제 생성하지 않음.
8. 단위 181개, 빌드·문법 검사 통과. 오늘/내일 나이스 실조회 각각 3식. 실제 사진 AI 및 OS 푸시 수신 미확인 상태를 안내에 명시.

화면 후보: v9-latest-plan.png (분할 계획·과목·컨디션), v9-latest-home-mobile.png (모바일 홈), v9-social.png (기존 실제 계정 연결 검증). 합성 데이터임을 포트폴리오에 명시할 것.

보안: 기존 관리자 immutable ID 보존, 기존 키·비밀번호·원본 학교 사진은 커밋하지 않음. 개인 메모/진행 기록은 자동 공유하지 않음. 시험용과 실제 외부 서비스 검증을 구분해 기록함.
