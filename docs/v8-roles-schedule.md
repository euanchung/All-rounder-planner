# v8 역할·관리자·학교 일과

## 권한

가입 때 학생/반장/부반장/선생님을 신청합니다. 선택만으로 권한을 얻지 않습니다. 선생님은 관리자가 신원을 확인해 승인하고, 반장·부반장은 학급 초대 코드로 연결한 다음 관리자 또는 담당 선생님이 지정합니다. 학생 개인의 할일·공부 기능은 그대로 사용할 수 있으며, 공지 게시와 할일 공유만 제한합니다.

관리자 페이지는 기존 소유자 계정의 불변 ID로만 접근합니다. 인증 서비스의 모든 가입자(첫 설정 미완료 포함)를 이름/이메일로 검색하고 50명씩 조회합니다. 역할 승인·변경, 이용 정지·복구, 공지/공유 기능 일시 중지, 전체 안내, 신고 처리가 가능합니다. 관리자 자신의 정지·권한 박탈은 차단합니다. 관리 작업은 감사 기록에 남습니다. 목록에는 개인 할일·대화 내용이 포함되지 않습니다.

승인된 선생님은 메인/소통/설정에서 학급 공지·시간표 편집, 학생 질문 답변, 공유 할일 직접 등록을 사용합니다. 개인 할일/주간 계획/공부 도우미는 숨기고 서버의 개인 할일 변경도 제한합니다. 반장·부반장은 학생 기능과 게시·공유 기능을 모두 사용합니다. 서버가 매 요청마다 권한·학급·정지 상태를 다시 검사합니다. 일반 메시지 전송은 학생에게도 허용합니다.

할일 공유는 승인된 역할만 분당 5회, 한국 날짜 기준 하루 30회까지입니다. 오류 시도도 제한에 포함될 수 있습니다. 학교/반 자동 그룹은 기존의 학급 인증·공개 동의·차단 정책을 유지합니다.

## 시간표와 계획

주간 계획은 일~토 7열, 일일 시간/남은 일일 시간/계획/여유를 숫자와 비율 막대로 보여줍니다. 회색은 사용·경과, 테마색은 계획, 초록은 여유입니다. 진행 기록이 없는데 시간 경과만으로 과제를 완료 처리하지 않습니다.

첫 설정 또는 시간표 편집에서 과목과 수업 시작/종료, 조회·식사·야자 등을 직접 입력합니다. 각 일과의 요일, 자정 넘김, 시험 기간 전용 여부를 저장합니다. 한국 시각의 현재 수업을 메인과 해당 칸에 표시합니다. 다음 주를 둘러봐도 현재 수업 표시는 실제 이번 주를 기준으로 합니다. 다른 학교에 특정 학교 예시를 자동 지정하지 않습니다.

제공된 학교 예시에는 08:05 조회, 1~9교시, 점심·청소·저녁, 19:10/20:10/21:30/22:30 자습, 화~목 21:00 간식이 포함됩니다. 23:40~다음 날 00:50의 4자습은 시험 기간 설정을 켤 때만 현재 일과로 활성화됩니다. 교사 이름과 원본 사진은 저장소에 넣지 않습니다.

## 시간표 사진 분석

2MB 이하 PNG/JPG/WebP를 올리고 전송 안내에 동의한 뒤 분석합니다. 기존 Gemini 직접 연결을 사용하며, 공부 도우미와 같은 한도(개인 5회/일, 사이트 30회/일·40회/월)를 공유합니다. 유료 결제나 자동 충전을 활성화하지 않습니다.

결과는 로그인한 본인에게만 보이는 `#settings/<분석 ID>`에서 다시 열 수 있습니다. 과목/시각을 채운 초안을 사람이 확인한 뒤 저장합니다. 사진 원본은 DB에 저장하지 않으며, 모델·사용량·결과·추정 비용을 저장합니다. 사진 안의 지시문은 명령이 아닌 자료로 다룹니다. 불명확한 내용은 확인 대상으로 안내합니다.

2026-09-08 실제 Gemini 사진 요청은 공급자 503으로 실패했습니다. 모델 목록/서버 연결 및 실패 시 수동 입력 보존은 확인했지만, 실제 사진 자동 인식 성공은 검증되지 않았습니다. 직접 입력과 예시 불러오기는 검증했습니다. 기존 무료 AI의 개인정보 안내와 운영상 제한은 v7 문서를 함께 참고하세요.

## 배포·검증

기존 DB에서 먼저 `node --env-file=.env.local scripts/migrate-campus.mjs`를 실행합니다. accounts/site/audit 테이블을 추가하고 서버 전용 권한으로 설정합니다. 기존 계정·할일을 삭제하지 않습니다.

로컬 단위 테스트 155개, 브라우저→API→실제 DB 통합 검사 67개 통과. 관리자 목록·검색·역할 변경·정지는 실제 DB의 합성 계정을 대상으로 내부 테스트 핸들러로 검증하고, 일반 회원의 관리자 HTTP 요청 차단을 확인했습니다. 관리자 화면은 테스트 데이터로 시각 검증했습니다. 실제 소유자 세션을 대신 로그인하지 않았으며, 관리자 ID 연결은 읽기 전용 조회로 확인했습니다. 생성한 검증 계정·메시지는 정리했습니다.
